# EndToEnd messaging agent 0.1.0 source candidate

**Current preparation checkpoint:** [steps 1–3 of the broader AGPL MVP plan are complete](STEPS_1_3_COMPLETION.md). The expanded scope, rights/dependency inventory, preferred-source supplements and current acceptance are separate from this historical device-agent candidate. Step 4's standalone persistent messaging package is next; no runnable 0.2.0 release or external publication is claimed.

This independently runnable agent performs messaging cryptography on the user's device. The browser runs its trusted unlock/identity controls at a separate origin; the local runner binds once to an authenticated loopback port zero. Product UI and relay implementations are separate consumers. This candidate preserves the original one-device/one-writer model; it does not promise Signal service interoperability or upstream support.

Agent/crypto/session sources are AGPL-3.0-only. Newly authored protocol/client sources are MIT; their LICENSE files apply to those packages only. Third-party source keeps its own license. See LICENSE, source/dependency manifests and docs/release/RIGHTS_DEPENDENCIES.md. Current unresolved review status is included honestly; this local candidate has not been approved for external publication.

## Build from source

Install the exact tools in docs/release/TOOLCHAIN.json, including Rust's wasm32-unknown-unknown target, wasm-pack, protoc, Node and Yarn. On the validated Windows GNU platform, point ENDTOEND_TOOLCHAIN_ROOT to the public tools directory containing mingw/mingw64/bin, protoc/bin and wasm-pack/wasm-pack-v0.15.0-x86_64-pc-windows-msvc. ENDTOEND_WASM_PACK may point directly to wasm-pack. No original developer checkout is required.

Run `yarn install --frozen-lockfile --ignore-scripts --non-interactive`, then `node scripts/release-build-crypto.mjs .`. Rust dependencies are supplied in dependencies/cargo and source replacement configuration is in packages/crypto/.cargo/config.toml. The Rust build is locked/offline and rejects an existing pkg-web/pkg-node directory; it never substitutes supplied WASM. Exact tool versions and output hashes are written to .build/crypto-build-proof.json.

Run `node --test packages/crypto/test/roundtrip.mjs`, `yarn workspace @e2ee/agent-browser build`, `yarn workspace @e2ee/agent test` and `yarn workspace @e2ee/client test`. The client test exchanges messages/files against an independently authored synthetic relay without the private product API. The local runner starts with `node --import tsx packages/agent/src/bin.ts` or its tested `node packages/agent/src/cli.mjs` bootstrap; consult its README for explicit relay/vault arguments and capability handling. Vault files are private runtime data and must stay outside the source directory. The browser agent's README and config.example.json document launch and the origin/source/nonce-checked handshake. The reference relay fixture is synthetic and is not a production hosting service.

After a successful source build, run `node scripts/release-reproduce-crypto.mjs . <new-isolated-directory>` to rebuild the crypto outputs at a different filesystem location and compare exact generated WASM/JavaScript/type/package hashes. Both builds use the same pinned toolchain, one Cargo job, a fixed SOURCE_DATE_EPOCH and remapped source paths. Success is recorded separately in .build/reproducibility-proof.json; it is not inferred merely because both builds succeed.

The local release directory also contains a separate MIT-only `endtoend-client-0.1.0.tar.gz`. It includes protocol/client source, a reference CLI, its isolated Yarn lock and a synthetic HTTP test. Its standalone install/test contains no agent, session, crypto or private product workspace. RELEASE_INDEX.json pairs all archives with their manifests and checksums. Runtime and client archive manifests are external sidecars so their own checksums can be verified without circular references.

The source archive contains preferred editable Rust/TypeScript, required protobuf/build files through Cargo vendoring, manifests/locks, protocol schemas, runners, tests, notices and build/install scripts. General-purpose compiler/interpreter/build tools are installed separately and pinned. No private product app, database, user record, key vault, attachment cache, credential or Git history is included.

Installed `node_modules` are excluded at every workspace depth. Unmodified binary test/example resources supplied by upstream vendored crates remain in those crates; they are not EndToEnd build outputs or a prebuilt product WASM fallback. Both source and runtime distributions carry dependency notice coverage under `dependencies/cargo-notices`, `dependencies/npm-notices`, `dependencies/upstream-notices` and `docs/release/third-party`. Run `yarn test:release` to check the source-inventory regression cases.

## Source availability and modification

The candidate's RELEASE_INDEX.json identifies exact source/runtime hashes and protocol version. An eventual public release must make its matching corresponding source available without a private repository login and present a prominent Source/License link in the trusted agent plus a source/license command in its local runner. The original Git repository may remain private. Hosting the source on another server does not transfer the operator's availability responsibility.

Keep the exact source candidate immutable while obtaining review. `node scripts/release-audit.mjs <extracted-source-directory> --review <external-review-decisions.json>` accepts the final review as a sidecar and verifies its reviewedSourceManifestSha256 against SOURCE_MANIFEST.json. Do not update the REVIEW_DECISIONS.json inside the candidate to approve its own hash: that would change the reviewed source manifest. Existing pending decisions accurately describe the point at which the candidate was created. No test or packaging script grants publication authority or a legal certification.

Changes from the pinned original baseline: extract the agent, add versioned protocol/trusted browser and local controls, move product clients to the transport and strengthen application persistence/isolation. Preserve notices and date modifications. Each current change is documented by the source manifest, feature matrix and release evidence; tests do not constitute a legal conclusion about private consumers.
